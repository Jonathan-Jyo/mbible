## 4. 할 일 (차례대로)

### ① 곡 목록에 사는 곳 (`js/praise-store.js`)
- 곡(`bible-praise-items`)에 `src: { at: "tj"|"link"|"app", path }` — 없으면 `app`. 판정 함수 하나(`srcOf(item)`)로 모든 곳이 본다
- `remove(id, keepAudio)` — `tj`·`link` 곡을 지울 때 **원본 파일은 지우지 않는다**(목록에서만). 지금 `app` 곡은 음원도 지운다 — 그대로

### ② 재생 (`js/play-engine.js` · 안드로이드)
- 엔진은 `ps-…` 곡을 지금 `PraiseAudio.getURL(id)`(앱 안 blob)로 연다(js/play-engine.js 87행 근처, `PraiseAudio` 는 js/praise-store.js 아래쪽). `src.at` 에 따라 갈라:
  - `tj` → `TjAudio.urlOf("praise/" + path)` 꼴의 `/_tojesus_/` 주소. **TojesusMedia 가 이미 두 길(파일·SAF)·Range 를 다 한다**
  - `link` → 새 주소(예: `/_praiselink_/<등록 번호>/<상대 경로>`). 안드로이드에 **등록된 위치 목록**을 두고 그 아래만 연다 — 아무 경로나 열지 않게(`TojesusLink.child()` 같은 정규 경로 검사)
    - 등록한 위치가 파일 길(모든 파일 접근)이면 `File`, 고른 폴더면 SAF 트리 — TojesusMedia 의 두 길과 같은 짜임으로
    - **새 주소를 만들면 `sw.js` 가 건드리지 않게** 넘긴다(지금 `/_tojesus_/` 를 넘기는 자리 옆에). 안드로이드는 PlayerHost · MainActivity(앱 화면·서비스 워커 길) 셋 다에 끼운다
- 빠르기는 지금처럼 말씀(tj: 오디오)만 — 매일찬양 곡은 `tj` 에 살아도 **늘 1배**(곡 id 가 `ps-` 라 그대로 된다 — 확인만)

### ③ 재등록 · 담기 (`js/tojesus-folder.js` · `js/praise-app.js`)
- 지금: 재등록이 tojesus/praise 의 새 곡을 세고 → `praise.html?collect=tojesus` → 담기 화면 → `_folderSong` 이 **조각으로 읽어 앱 안에 복사**(HymnTree `openRead/readNext`)
- 바꿀 것: 이 길에서는 **복사하지 않고** `src: { at: "tj", path: "<praise 기준 경로>" }` 로 등록. 담기 화면(분류·채널·태그)은 그대로
- 이미 담은 곡 표시(`bible-praise-tojesus-done`)는 그대로 쓴다
- 재등록이 `tj` 곡 중 **원본이 없어진 것**을 세어 알린다(🚫 표시와 함께)

### ④ 매일찬양 ⚙ — 「위치 등록」 · 「모으기」 (`praise.html` · `js/praise-app.js` · `HymnTreePlugin`)
- **위치 등록**: 폴더(또는 곡)를 골라 `link` 로. 고르는 길은 지금의 「🎵 음악 모으기」(HymnTree `slot: "music"`)와 같은 장치를 쓰되 **복사하지 않는다**
  - 위치 목록은 안드로이드가 기억(여러 곳 가능). 같은 곡을 `link` 와 `tj` 로 두 번 담지 않게 — 담을 때 제목·연주자로 견준다(지금 규칙)
- **모으기**: `link`·`app` 곡(또는 다른 폴더 곡)을 `tojesus/praise/<앨범>/` 으로. **복사 / 이동** 을 그때 고른다
  - 이동은 원본을 지우므로 한 번 더 묻고, 다 옮긴 뒤 몇 곡인지 알린다
  - `app` 곡을 모으면 앱 안 사본을 폴더로 써낸 뒤 **앱 안 사본을 지울지 묻는다**
  - 쓰는 손발은 TojesusFolder 쪽(파일 길/SAF 길 둘 다)에 새로 둔다 — 지금 `zipExtract` 의 `Sink`(FileSink·SafSink) 짜임을 그대로 빌려 쓰면 된다
- 지금의 「🎵 음악 모으기」(앱 안 복사) 단추는 **tojesus 연결이 없을 때만** 남긴다(그때만 `app`)

### ⑤ 함께 고칠 곳
- **찬양 알람** `js/alarm-sync.js` — 알람 곡을 앱 전용 폴더로 미리 복사해 두는데(앱이 꺼져 있어도 울리게), 지금은 원본을 앱 안 저장소에서 꺼낸다 → `src` 에 따라(앱 안 / tojesus / 등록 위치) 읽게. 원본이 없으면 그 곡을 건너뛰고 알린다
- **보이지 않는 음원 정리 · 음원 진단**(`PraiseAudio.orphans/reconcile` 등) — `app` 곡에만 해당되게(`tj`·`link` 곡을 「음원 없음」으로 지우지 않게)
- **백업** `js/backup-core.js` — 곡 목록에 `src` 가 함께 들어간다. 음원은 폴더에 있으므로 담지 않는다(지금 `praise` 칸의 `heavy` 음원 옵션은 `app` 곡에만 의미)
- **🚫 표시** — 원본이 없는 곡: 목록에 🚫, 누르면 「위치 다시 찾기」(link) 또는 「tojesus/praise 에 다시 넣고 재등록」(tj)

## 5. 빠뜨리기 쉬운 것 (5.29 에서 실제로 걸린 것)

- **안드로이드 10 이하 + SD카드**는 파일 길로 **쓸 수 없다** — `TojesusLink.canWrite()` 가 판정. 「모으기」(복사·이동)·이동의 원본 지우기가 여기 걸린다 → 5.29.1 처럼 「다른 폴더 고르기(SAF)」로 안내
- 고른 폴더(SAF)가 살아 있는지는 **권한 + 그 폴더가 실제로 있는지**까지 `TojesusLink.pickedTree()` 한 곳에서 본다 — 판정을 따로 만들지 않는다
- 연결을 바꿀 때 옛 연결은 **새 연결이 된 뒤에** 놓는다(먼저 놓으면 취소하는 순간 잘 되던 연결까지 잃는다)
- 자동 연결(파일 길)일 때 HymnTree 칸은 `adopt({ uri: "file:<tojesus 절대 경로>", sub })` 로 넘겨받고, `uri()` 는 `/_tojesus_/…` 를 준다 — 웹은 그 주소를 `convertFileSrc` 에 넣지 않는다(js/hymn-folder.js)
- 바뀐 JS·CSS 는 html 의 `?v=` 를 올리고 `sw.js` 의 `APP_VER` 도 올린다. 새 화면 파일은 `scripts/sync-www.sh` · `scripts/build-light.sh` 목록에
- 높이는 `dvh` 만 쓰지 않는다 — `90vh; 90dvh` 두 줄(노트 34). 가운데 띄운 창은 `max-height` + 창 안 스크롤(노트 33)
- 곡 이름의 번호를 읽어야 하면 `TjAudio.chapterMap()`(이름 뒤 숫자도 읽는다)

# 판 나누기 — Salt / light

**2026-08-09 정리** · `항상예수께로 Salt v5.0` · `항상예수께로_light v3.0.1`

---

## 1. 왜 나눴나

느려서 쓰지 않고 노는 구형 태블릿이 집집마다 있다. 웬만한 앱은 답답해서 못 쓰지만,
**말씀 읽고 찬미가 부르는 데는 충분하다.** 오히려 유튜브 같은 유혹이 없어 더 낫다.

문제는 앱이 무거워진 것이었다. 그래서 **무엇이 무거운지부터 쟀다.**

| | |
|---|---|
| audio (기본 음성 52개) | **137 MB — 전체의 82%** |
| data (성경 본문 66권) | 41 MB |
| images (암송 그림연상 59장) | 13 MB |
| **코드 전부** | **3 MB** |

**"프로그램이 무거워서 느리다"가 아니라 "짐이 무거운 것"이었다.** 코드는 3MB뿐이다.
그러니 옛 버전을 되살릴 이유가 없었다 — 지금 코드에서 짐만 덜면 됐다.

### 옛 버전 보관 문제

개발자들이 "예전 간단한 버전은 안 갖고 있다"고 하는 것은 대개 **빌드된 APK**를 말한다.
소스는 `git`에 남아 있지만, 꺼내도 **그 시절 빌드 환경**(옛 JDK·SDK·Gradle)이 없으면
빌드되지 않는다. 그래서 되살리기가 어렵다.

**이 방식은 그 문제를 피한다.** 코드 한 벌에서 담는 자산만 달리한다.
앞으로 고치는 것이 두 판에 그대로 반영되므로, 보관할 옛 버전 자체가 없다.

## 2. 무엇이 다른가

| | **Salt** | **light** |
|---|---|---|
| 판 | v5.0 | v3.0.1 |
| APK | 167 MB | **14 MB** |
| appId | `com.jonathan.biblemem` | `com.jonathan.biblemem.light` |
| 담긴 앱 | 여섯 모두 | 성경읽기 · 성경암송 · 찬미가 |
| 성경 역본 | 9개 | 7개 (새번역·화합본 번체 뺌) |
| 기본 음성 · 그림연상 | 있음 | 없음 |
| 홈 달력 | 다섯 앱 | **읽기 · 암송 둘만** |
| 웹 | mbible.netlify.app | mbiblem.netlify.app |

**14MB — 12배 가벼워졌다.** 34MB로 예상했는데 더 줄었다. 성경 JSON에서 빈칸을 빼자
APK 압축이 크게 먹혔다. 성경 66권은 그대로다.

**appId를 나눴으므로 한 기기에 둘 다 깔린다.** 다만 자료는 서로 나뉜다 —
한쪽에서 담은 것이 다른 쪽에 나타나지 않는다.

## 3. 어떻게 만드나

```bash
bash scripts/build-apks.sh          # 두 판 APK
bash scripts/build-apks.sh light    # 가벼운 판만
bash scripts/build-light.sh         # 가벼운 웹 자산(www-light/)만
```

### 짜임

**안드로이드 제품 갈래(flavor)** 로 나눈다. 코드는 한 벌이다.

```
full   → 항상예수께로 Salt        assets: src/full/assets/public   (194MB)
light  → 항상예수께로_light       assets: src/light/assets/public  ( 34MB)
```

**자산을 갈래별 자리에 두는 것이 핵심이다.** `cap sync`는 늘 `src/main/assets`에 쓰는데,
거기 두면 어느 갈래에나 들어가 light에도 audio 137MB가 딸려 간다.
그래서 `build-apks.sh`가 sync 뒤에 `src/full/`로 옮긴다.

**앱 이름·꾸러미 이름은 `resValue`로** 갈래마다 넣는다. `strings.xml`에도 같은 이름이
있으면 충돌해 빌드가 막히므로, 그쪽은 비워 두었다.

### 화면은 한 벌 — 실행할 때 갈린다

화면 파일을 두 벌로 나누지 않았다. **두 벌이 되면 반드시 어긋난다.**

`build-light.sh`가 표시 한 줄짜리 파일을 만들고 `index.html` 맨 앞에 끼운다.

```js
window.LIGHT_EDITION = true;
window.LIGHT_VERSION = "v3.0.1";
```

허브가 이것을 보고 **담기지 않은 앱을 감춘다** — 기도·나눔·회고 단추, 그리고
종합달력의 해당 칸. 달력은 `SOURCES`를 한 곳에서 거르므로, 거기만 막으면
달력 점·날짜별 요약·대시보드·연속기록이 함께 따라온다.

찬미가는 매일찬양 안에 들어 있어 그 화면을 남기되, 허브에서는 이름만 **찬미가**로 보인다.

## 4. 버전 규칙

| 무엇을 고쳤나 | Salt | light |
|---|---|---|
| **둘 다** (공통 코드) | 5.0 → **5.1** | 3.0 → **3.1** |
| **Salt만** | 5.0 → **5.0.1** | 그대로 |
| **light만** | 그대로 | 3.0 → **3.0.1** |
| 아주 큰 변화 | 6.0 — **사용자가 따로 말할 때만** | |

**둘째 소수점 = "이 판만 고쳤다"** — 양쪽에 똑같이 적용된다.

- 앞자리는 임의로 올리지 않는다. 아껴 쓴다.
- `versionCode`(안드로이드 내부 번호)는 빌드마다 +1. 이것을 안 올리면 설치가 막힌다.
  보이는 이름과 별개다. 지금 **85**.
- 라이트 화면의 판 번호는 `build-light.sh`의 `LIGHT_VERSION`이 정한다 — 함께 고칠 것.

## 5. 배포

```bash
npx netlify deploy --prod --dir www       --site 2b2dc16d-188b-4401-928b-2cd94ef52af9   # mbible
npx netlify deploy --prod --dir www-light --site 77f3f03d-9c0b-40d9-8e3e-e14096751280   # mbiblem
```

Netlify는 사이트 하나가 폴더 하나를 가지므로 **각각 올릴 수밖에 없다.**
한 사이트에 합쳐 `/light/`로 나누는 길도 있으나, 성경 자료 41MB가 두 벌 올라가고
주소가 헷갈려 권하지 않는다.

## 6. 검증한 것

| | Salt | light |
|---|---|---|
| APK 안 audio | 52개 | **0개** |
| APK 안 images | 59개 | **0개** |
| 성경 자료 | 66권 | **66권** |
| 웹 `/audio/` | 200 | **404** |
| 웹 `/pray.html` | 200 | **404** |
| 새번역(`ko_new`) | 있음 | **없음** |
| 홈 단추 | 여섯 | **셋** |
| 홈 달력 칸 | 여섯 | **둘** |
| 화면 판 번호 | v5.0 | **v3.0.1** |

다섯 앱 기록을 모두 심어 두고 달력을 확인했다 — light는 날짜 칸을 눌러도
기도·찬양·나눔이 나오지 않는다.

## 7. 남은 것

### 옛 WebView 문법 — 아직 손대지 않았다

light가 노리는 구형 태블릿에서 **화면이 하얗게 뜰 수 있다.**

코드에 `?.`(optional chaining)가 **100곳** 있다. 크롬 80(2020) 이상에서만 도는 문법이라,
그보다 낡은 WebView에서는 앱이 통째로 안 켜진다.

| WebView | |
|---|---|
| 크롬 80 이상 | 잘 됨 |
| 크롬 63~79 | **하얀 화면** |

**다행인 것** — WebView는 안드로이드 7부터 플레이스토어로 따로 갱신된다.
그동안 업데이트를 받아 온 기기는 대개 크롬 100대라 잘 돈다.
**진짜 변수는 안드로이드 판이 아니라 "얼마나 오래 방치됐나"이다.**

변환 도구(esbuild·babel 등)가 이 맥에 없어 이번엔 손대지 않았다.
손으로 100곳을 고치면 새 버그가 날 위험이 크다.

→ **먼저 그 태블릿에 깔아 보고**, 하얀 화면이면 그때 도구를 들여 제대로 변환한다.

### 설치 한계

```
minSdkVersion 24   → 안드로이드 7.0 (2016) 이상
targetSdkVersion 36
```

`target 36`은 "최신에 맞춰 만들었다"는 뜻이지 "최신에서만 된다"는 뜻이 아니다.
설치 가능 여부는 `min`이 정한다.

### 그 밖

- 라이트에서 매일찬양 화면이 함께 따라온다(찬미가가 그 안에 있어서). 억지로 떼면
  위험이 커 그대로 두었다.
- 두 판의 자료가 나뉘어 있어, 옮기려면 `⚙ 설정 › 데이터 백업`의 `.zip`을 써야 한다.

## 8. 곁들여 정한 것

이 판 나누기를 하면서 함께 정해진 것들.

- **이름** — `Salt`와 `light`. 소금과 빛(마 5:13-14).
- **사용설명서** — [`docs/사용설명서.md`](사용설명서.md). Salt 기준으로 쓰고, 8장에
  두 판 차이·백업·SD카드 정리를 모았다. **light 설명서를 따로 쓸 필요가 없다.**
- **SD카드에 음원 두기** — exFAT이어야 하고, 맥에서 복사했다면 `._`로 시작하는
  찌꺼기를 지우고 빼야 한다. 안드로이드에는 깨진 파일로 보인다.
  (설명서 8장에 지우는 명령이 있다)

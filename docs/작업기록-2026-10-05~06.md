## 재생 구조 (5.18.0 부터) — 고칠 때 먼저 볼 곳

- 소리는 **엔진 한 곳**만 낸다: `player.html` + `js/play-engine.js` (APK 에서는 `PlayerHost.java` 가 1픽셀 WebView 로 띄움)
- 화면(매일찬양·매일기도·relay-bar)은 `PlayEngine.cmd(...)` 로 명령, `PlayEngine.subscribe` 로 상태를 받는 리모컨
- 알림·잠금화면·이어폰: `BgPlayService.java`(포그라운드 서비스 + MediaSession) ↔ `js/bg-play.js`(엔진 화면에 붙음)
- 브라우저(웹판)는 같은 엔진을 화면 안에서 돌리고 `PlayRelay` 로 다음 화면에 넘긴다
- 앱 안에서 다른 소리(찬미가 반주 등)를 틀면 찬양 엔진은 멈춘다 — 안드로이드 오디오 포커스(의도된 동작으로 둠)

## 알게 된 함정

- **Capacitor `call.getLong`·`getDouble` 은 JS 정수(Integer)를 못 읽고 기본값을 준다** → `call.getData().optLong/optDouble` 로 읽는다.
  이것 때문에 음악 모으기의 크기 한도가 무시돼 72MB 를 통째로 읽다 앱이 꺼졌다(에뮬레이터 실측)
- 삼성 태블릿: 폴더(content://)를 웹 주소로 가져오면 알맹이가 제대로 안 온다 → `HymnTree.read` 로 직접 읽는다(찬미가·음악 모으기 같은 길)
- 한 곡을 화면으로 넘기는 동안 파일 크기의 4~6배 메모리가 든다 → 한 곡 20MB 한도
- 판 없이 `indexedDB.open(이름)` 하면 저장소 없는 빈 DB 가 생겨 주인이 영영 못 쓴다 → `backup-core.js` 는 없는 DB 를 만들지 않는다
